# 写出好 Skill 的尺子

这是一份参考手册，不执行具体业务任务。新建或体检 skill 时逐条对照。

## 1. 触发方式

- **user-invoked（显式命令）**：在 frontmatter 加 `disable-model-invocation: true`，适合提交、批量修改等有副作用或不应自动执行的动作。
- **model-invoked（自动触发）**：不加该字段，适合明确的分析纪律和只读流程。
- 既要自动又要手动时，在 description 中写清自动触发边界，避免过度打扰。

## 2. description 决定命中率

- 把“什么时候用”放在前面，使用用户实际会说的中文场景词和关键术语。
- 写清典型任务、适用模块和必要类名，但不要堆砌无关关键词。
- description 说“何时用”，正文说“怎么做”，避免整段重复。
- 与现有工具职责重叠时明确边界，必要时优先复用现有工具。

## 3. 信息层次

1. **正文步骤**：需要照做的流程，写成有序步骤。
2. **Skill 内参考**：表格、清单、模板与独立脚本，和主体步骤分开。
3. **Skill 外参考**：链接 `.claude/md/`、`.claude/memory/`、相关 agents 或具体代码文件，不复制外部内容。

项目内路径使用相对地址；不要写死盘符或机器路径。

## 4. 粒度

- 自动纪律与有副作用的手动命令分开。
- 长流程中只有能独立调用的阶段才拆开。
- 总是一起使用且没有独立价值的内容不要为拆而拆。
- Agent 负责独立任务，Skill 负责流程/知识；不要用同一内容重复维护两份全文。

## 5. 单一真实源

- 一个事实只维护一处。CLAUDE.md 已有规则直接遵循或引用，不在 skill 中复制成长段落。
- 与 `.claude/memory/` 重叠时链接对应条目，避免未来漂移。
- 删除“仔细思考”等无信息量指令、客套话和 no-op。
- 代码/API 说明必须与实际文件核对，不写推测路径；无法确认时明确标注。

## 6. 使用清晰术语

- 使用“红绿重构”“幂等”“单一真实源”“可证伪假设”等标准概念。
- 避免生造黑话；IL 专属术语首次出现时给出一句解释或链接。
- 示例使用 PowerShell 优先，并保持可执行、无伪造结果。

## 7. 常见失败模式

- 步骤未走完就收尾；流程类 skill 应写明完成标准。
- description 与正文、skill 与 CLAUDE.md、skill 与记忆之间大段重复。
- 一个 skill 塞入所有主题，导致触发模糊。
- description 空泛，自动触发无法命中。
- 复制其他项目内容后残留业务类、绝对路径、记忆链接或不存在的脚本。

## 体检已有 Skill

逐项核对上述规则，重点检查触发词、内容重复、粒度、路径、依赖链接和实际代码一致性。只修复确认的问题；修改后更新 `.claude/memory/toolkit-index.md`（若用途有变化），并在任务总结中列出实际改动。
